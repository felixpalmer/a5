# A5 for R

> A5 is a discrete global grid system (DGGS) that divides the Earth into equal-area pentagonal cells, at 31 resolutions from the whole world down to 30mm², each identified by a 64-bit integer.

This is the A5 1.0.0-beta.3 documentation for the `a5R` CRAN package (docs: https://belian-earth.github.io/a5R/). Cell IDs are `a5_cell` vectors. Code samples are in R only, and function headings use the R names. Parameter names and types in the descriptions follow the TypeScript API: `bigint` is a cell ID, and `camelCase` parameters are `snake_case` in Python, Rust, DuckDB and R. Documentation for other languages is listed at https://a5geo.org/next/llms.txt.

---

Source: https://a5geo.org/next/docs

A5 is a geospatial index that partitions the world into [pentagonal cells](https://a5geo.org/next/examples/teohedron). The cells are available at [31 resolution levels](https://a5geo.org/next/examples/hierarchy), from a handful covering the whole world down to less than 30mm², and every cell at a given resolution has [exactly the same area](https://a5geo.org/next/examples/area). Each cell is identified by a 64-bit integer, which is frozen from v1.0: an A5 cell ID stored today will refer to the same place in the future.

Once data is in cells, very different datasets can be joined, aggregated and compared directly: points can be counted per cell, as with the [density of holiday rentals](https://a5geo.org/next/examples/airbnb) across a city, and regions such as countries or parcels of land become [coverings](https://a5geo.org/next/docs/api-reference/coverings.md), sets of cells which support union, intersection and difference.

## Key strengths

- **Equal area, single topology**: every cell is an exactly equal-area pentagon with 5 neighbors, so aggregates are free of bias from unequal cell sizes. See [A5 vs H3](https://a5geo.org/next/docs/recipes/a5-vs-h3.md).
- **Built for big data**: cell IDs follow a [space-filling curve](https://a5geo.org/next/examples/teohedral-curve) that never crosses itself, so polygons and coverings are compact ID ranges. Billions of cells can be filled, combined and counted in seconds.
- **Fast & rich API**: high-level functions for [indexing](https://a5geo.org/next/docs/api-reference/indexing.md), [hierarchy](https://a5geo.org/next/docs/api-reference/hierarchy.md), [traversal](https://a5geo.org/next/docs/api-reference/traversal.md) and [coverings](https://a5geo.org/next/docs/api-reference/coverings.md), with a native Rust core.
- **Strong ecosystem**: official libraries for [TypeScript](https://a5geo.org/next/docs/quickstart/javascript.md), [Python](https://a5geo.org/next/docs/quickstart/python.md) and [Rust](https://a5geo.org/next/docs/quickstart/rust.md), with [DuckDB](https://a5geo.org/next/docs/quickstart/duckdb.md), [PostgreSQL](https://a5geo.org/next/docs/quickstart/postgresql.md), R, QGIS and deck.gl integrations. See the [Ecosystem](https://a5geo.org/next/docs/ecosystem.md).

# Indexing

Functions for converting between geospatial coordinates and A5 indices.

Coordinates are specified as per the [GeoJSON spec](https://www.rfc-editor.org/rfc/rfc7946#section-3.1.1), namely: `[longitude, latitude]`.

:::info
For detailed information about how A5 encodes cells as 64-bit integers, see [Index Encoding](https://a5geo.org/next/docs/technical/index-encoding.md).
:::

### a5_lonlat_to_cell

Indexes the coordinate at a given resolution to an A5 cell index.

```r
a5_lonlat_to_cell(lon, lat, resolution)
```

#### Parameters

- `coordinate` **(number[])** coordinate as `[longitude, latitude]`
- `resolution` **(number)** The resolution level to index at

#### Return value

- **(bigint)** The A5 cell identifier

### a5_cell_to_lonlat

Returns the geospatial coordinate at the center of an A5 cell.

```r
a5_cell_to_lonlat(cell, as_dataframe = FALSE)
```

#### Parameters

- `cell` **(bigint)** A5 cell identifier

#### Return value

- **(number[])** The center coordinate as `[longitude, latitude]`

### a5_cell_to_boundary

Returns the vertices that define the boundary of an A5 cell.

```r
a5_cell_to_boundary(cell, format = c("wkb", "wkt"), closed = TRUE, segments = NULL)
```

#### Parameters

- `cell` **(bigint)** A5 cell identifier
- `options` **(object)** Optional configuration object
  - `closedRing` **(boolean)** Whether to close the ring by repeating the first point at the end. Defaults to `true`.
  - `segments` **(number | 'auto')** Number of segments to use for each edge. When set to 'auto', uses a resolution-appropriate value. Defaults to 'auto'.

#### Return value

- **(number[][])** Array of coordinates defining the cell boundary, each as `[longitude, latitude]`

### a5_polygon_to_cells

Returns all cells within a polygon, defined either by a single ring of `[longitude, latitude]` vertices or by GeoJSON-style rings `[outer, ...holes]`. Cells inside a hole are excluded.

Rings may be open or closed (GeoJSON-style, with the first vertex repeated at the end) — closure is automatic either way. Either winding order is accepted; the orientation is detected from the ring geometry. Hole rings with fewer than 3 distinct vertices are ignored.

The `containment` option controls which cells count as belonging to the polygon:

- `'center'` (default) — a cell is included only if its center lies inside the polygon. Adjacent polygons that share an edge produce disjoint coverings, so this is the right choice for partitioning.
- `'overlapping'` — additionally includes every cell that overlaps the polygon boundary. The result is a superset of `'center'` that fully covers the polygon with no gaps, at the cost of some overlap with adjacent polygons. Use this when a query must not miss any cell touching the polygon (for example, filtering database rows by cell before applying an exact geometry test).

The result is a [covering](https://a5geo.org/next/docs/api-reference/coverings.md) of the polygon, approximating it with `'center'` and containing it with `'overlapping'`: compacted cells, then a [compaction marker](https://a5geo.org/next/docs/api-reference/compaction.md#coverings-and-the-compaction-marker) recording the resolution. Use [`a5_uncompact`](https://a5geo.org/next/docs/api-reference/compaction.md#uncompact) to expand it to the input resolution. The compacted form is intended for storage, transfer and set operations: cell boundaries of different resolutions do not nest geometrically, so the mixed-resolution cells of a covering will show overlaps and gaps when rendered. Uncompact to a single resolution before drawing cells on a map.

Multi-polygons are not supported directly — call `a5_polygon_to_cells` per polygon and combine the results with [`a5_union`](https://a5geo.org/next/docs/api-reference/coverings.md#union). Coverings can also be intersected, subtracted and tested for containment without uncompacting, see [Coverings](https://a5geo.org/next/docs/api-reference/coverings.md).

```r
a5_polygon_to_cells(x, resolution, containment = c("centre", "overlapping"))
```

#### Parameters

- `polygon` **(LonLat[] | LonLat[][])** Either a single ring of `[longitude, latitude]` vertices, or an array of rings where the first ring is the outer boundary and subsequent rings are holes. The outer ring must contain at least 3 vertices.
- `resolution` **(number)** Target resolution (0–30)
- `options` **(object)** Optional configuration object
  - `containment` **('center' | 'overlapping')** Which cells to include relative to the polygon. `'center'` includes a cell only if its center is inside; `'overlapping'` also includes cells that touch the polygon, for gap-free coverage. Defaults to `'center'`.

#### Return value

- **(BigUint64Array)** Compacted cells belonging to the polygon sorted in curve order, then the [compaction marker](https://a5geo.org/next/docs/api-reference/compaction.md#coverings-and-the-compaction-marker). A polygon with no cells gives just the [compaction marker](https://a5geo.org/next/docs/api-reference/compaction.md#coverings-and-the-compaction-marker)

#### Example

_Not yet in a released version for R._

```r
library(a5R)

# Bounding box around central Paris
paris <- wk::wkt("POLYGON ((2.25 48.81, 2.42 48.81, 2.42 48.9, 2.25 48.9, 2.25 48.81))")
compact <- a5_polygon_to_cells(paris, resolution = 10)
flat <- a5_uncompact(compact)  # all cells at resolution 10

# The same polygon with a hole — cells inside the hole are excluded
with_hole <- a5_polygon_to_cells(wk::wkt(
  "POLYGON ((2.25 48.81, 2.42 48.81, 2.42 48.9, 2.25 48.9, 2.25 48.81),
            (2.3 48.84, 2.37 48.84, 2.37 48.87, 2.3 48.87, 2.3 48.84))"
), resolution = 10)

# Full coverage — every cell overlapping the polygon, with no gaps along the edge
covering <- a5_polygon_to_cells(paris, resolution = 10, containment = "overlapping")
```

### a5_linestring_to_cells

Returns all cells whose pentagons intersect a polyline defined by a sequence of waypoints. Consecutive waypoints are connected with great-circle arcs. For a simple two-point line segment, pass `[start, end]`.

The result is uncompacted at the requested resolution and is not sorted — cells appear roughly in the order they were discovered along the path. Cells at waypoint junctions are deduplicated.

```r
a5_linestring_to_cells(x, resolution)
```

#### Parameters

- `waypoints` **(LonLat[])** Polyline vertices, each as `[longitude, latitude]`
- `resolution` **(number)** Target resolution (0–30)

#### Return value

- **(bigint[])** Array of unique cell identifiers whose pentagons intersect the polyline

#### Example

```r
library(a5R)

# Simple segment: Paris → London
segment <- a5_linestring_to_cells(wk::wkt("LINESTRING (2.3522 48.8566, -0.1276 51.5074)"), resolution = 8)

# Multi-waypoint route: Paris → Lyon → Nice
route <- wk::wkt("LINESTRING (2.3522 48.8566, 4.8357 45.764, 7.262 43.7102)")
cells <- a5_linestring_to_cells(route, resolution = 8)
```

## Cell representation

A5 cells are stored as 64 bit integers, for performance and to provide a compact representation for use in databases. In JavaScript these can be represented as [BigInt](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/BigInt) values and arrays of cells stored as [BigUint64Array](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/BigUint64Array)s.

For best performance it is recommended to use this representation, but it is also possible to convert them into hexadecimal, for example to encode them in JSON (which does _not_ support 64 bit integers). Two helper functions are provided for this conversion.

### a5_u64_to_hex

```r
a5_u64_to_hex(x)
```

#### Parameters

- `index` **(bigint)** A5 cell identifier

#### Return value

- **(string)** Hexadecimal string representation of the cell identifier

### a5_hex_to_u64

```r
a5_hex_to_u64(x)  # returns an a5_cell
```

#### Parameters

- `hex` **(string)** Hexadecimal string representation of an A5 cell identifier

#### Return value

- **(bigint)** The A5 cell identifier

# Hierarchy

The A5 tiling system supports subdividing the world all the way from the 12 dodecahedron faces at resolution 0 to millimeter-scale leaf cells.

The cells are arranged in a logical hierarchy, with each cell having an integer resolution. Each cell has one parent cell at the previous resolution level and 4 child cells at the next resolution level, except at the ends of the hierarchy: the 12 resolution 0 cells, representing the dodecahedron faces, have 5 children each and the [world cell](https://a5geo.org/next/docs/technical/index-encoding.md#special-case-world-cell) as their parent, while leaf cells at resolution 30 have no children.

### Parent and child cells overlap, they do not nest

The hierarchy is a logical grouping rather than an exact geometric containment. Pentagons cannot be subdivided into smaller pentagons, so a child cell overlaps its parent without lying entirely inside it: on average about 63% of a child's area falls within its parent, and at least about 7%, so no child ever lies entirely outside its parent. Treat `a5_cell_to_parent`, `a5_cell_to_children` and [compaction](https://a5geo.org/next/docs/api-reference/compaction.md) as a way of grouping nearby cells, not as an exact containment test.

The relationship is loosest between resolutions 1 and 2. Each resolution 1 cell is the single pentagon of its [quintant](https://a5geo.org/next/docs/technical/teohedron.md#resolution-1), anchored at the center and a corner of the dodecahedron face and reaching into the neighboring quintants, while its four children are the resolution 2 cells that tile the quintant itself. On average about 58% of a child falls within its parent, rather than 63%, while the least-covered child still has about 7%, as at every other resolution. This is the price of keeping every cell a pentagon: the alternative, triangular resolution 1 cells, nests more closely but breaks the single cell shape and gives resolution 1 cells many awkward vertex-only neighbors.

### Spatial hierarchy: subcells and supercells

Where the parent/child relationship groups cells by index, subcells and supercells group them by location: a finer cell belongs to the coarser cell that contains its center. Every cell at one resolution is then the subcell of exactly one cell at each coarser resolution, so aggregating fine data by supercell attributes each value to the coarse cell it actually lies in. This costs more than `a5_cell_to_parent` / `a5_cell_to_children`, which are pure bit operations.

### a5_cell_to_supercell

Returns the cell at a coarser resolution that contains the center of an A5 cell: the spatial counterpart of `a5_cell_to_parent`.

_Not yet in a released version for R._

```r
a5_cell_to_supercell(cell, resolution = NULL)
```

#### Parameters

- `index` **(bigint)** A5 cell identifier
- `resolution` **(number)** Target resolution, at most the cell's own

#### Return value

- **(bigint)** The cell at `resolution` containing the center of `index`

### a5_cell_to_subcell

Returns the cells at a finer resolution whose centers lie in an A5 cell: the spatial counterpart of `a5_cell_to_children`, and the inverse of `a5_cell_to_supercell`. Like the other functions returning a [covering](https://a5geo.org/next/docs/api-reference/coverings.md), the result is compacted, ending with a [compaction marker](https://a5geo.org/next/docs/api-reference/compaction.md#coverings-and-the-compaction-marker) recording the resolution.

_Not yet in a released version for R._

```r
a5_cell_to_subcell(cell, resolution = NULL)
```

#### Parameters

- `index` **(bigint)** A5 cell identifier
- `resolution` **(number)** Target resolution, at least the cell's own

#### Return value

- **(BigUint64Array)** Compacted subcells sorted in curve order, then the [compaction marker](https://a5geo.org/next/docs/api-reference/compaction.md#coverings-and-the-compaction-marker) — use [`a5_uncompact`](https://a5geo.org/next/docs/api-reference/compaction.md#uncompact) to expand them. Resolution 30 covers only part of the world, so for a cell reaching past it the subcells are given at resolution 29.

#### Example

_Not yet in a released version for R._

```r
library(a5R)

cell <- a5_lonlat_to_cell(2.35, 48.85, resolution = 8)
subcells <- a5_uncompact(a5_cell_to_subcell(cell, resolution = 11))
all(a5_cell_to_supercell(subcells, resolution = 8) == cell)  # TRUE
```

# Traversal

Functions for finding neighboring cells and collecting cells within a range. See the [Traversal](https://a5geo.org/next/examples/traversal) example.

Each A5 cell has exactly 5 edge neighbors, which can be obtained using the `a5_grid_disk` function. If the vertex neighbors are required, `a5_grid_disk` can be used. For broader range queries `a5_spherical_cap` provides all the cells within a great-circle radius. To trace cells along a path, use [`a5_linestring_to_cells`](https://a5geo.org/next/docs/api-reference/indexing.md#linestringtocells).

In order to save memory, the returned cells from `a5_grid_disk`, `a5_grid_disk` and `a5_spherical_cap` are [compacted](https://a5geo.org/next/docs/api-reference/compaction.md) into a [covering](https://a5geo.org/next/docs/api-reference/coverings.md): the cells, then a [compaction marker](https://a5geo.org/next/docs/api-reference/compaction.md#coverings-and-the-compaction-marker) recording their resolution. Coverings can be combined with the [set operations](https://a5geo.org/next/docs/api-reference/coverings.md).

### a5_grid_disk

Returns all cells within `k` edge-sharing hops of a center cell.

At each step, only edge-sharing neighbors (5 per cell) are followed.

The result is compacted — use [`a5_uncompact`](https://a5geo.org/next/docs/api-reference/compaction.md#uncompact) to expand it to the resolution of the center cell.

```r
a5_grid_disk(cell, k, vertex = FALSE)
```

#### Parameters

- `cellId` **(bigint)** Center A5 cell identifier
- `k` **(number)** Number of hops (0 returns just the center cell)

#### Return value

- **(BigUint64Array)** Compacted cells in the disk sorted in curve order, then the [compaction marker](https://a5geo.org/next/docs/api-reference/compaction.md#coverings-and-the-compaction-marker)

#### Example

_Not yet in a released version for R._

```r
library(a5R)

cell <- a5_lonlat_to_cell(2.3522, 48.8566, resolution = 10)
ring1 <- a5_grid_disk(cell, k = 1)  # center + 5 edge neighbors (compacted)
ring2 <- a5_grid_disk(cell, k = 2) |> a5_uncompact()  # center + ring 1 + ring 2 (uncompacted)
```

### a5_grid_disk

Returns all cells within `k` hops of a center cell, following both edge-sharing and vertex-sharing neighbors.

The result is compacted — use [`a5_uncompact`](https://a5geo.org/next/docs/api-reference/compaction.md#uncompact) to expand it to the resolution of the center cell.

```r
a5_grid_disk(cell, k, vertex = TRUE)
```

#### Parameters

- `cellId` **(bigint)** Center A5 cell identifier
- `k` **(number)** Number of hops (0 returns just the center cell)

#### Return value

- **(BigUint64Array)** Compacted cells in the disk sorted in curve order, then the [compaction marker](https://a5geo.org/next/docs/api-reference/compaction.md#coverings-and-the-compaction-marker)

### a5_spherical_cap

Computes all cells whose centers fall within a great-circle radius from the center of a given cell.

The result is compacted — use [`a5_uncompact`](https://a5geo.org/next/docs/api-reference/compaction.md#uncompact) to expand it to the resolution of the center cell.

```r
a5_spherical_cap(cell, radius)
```

#### Parameters

- `cellId` **(bigint)** Center A5 cell identifier
- `radius` **(number)** Radius in meters

#### Return value

- **(BigUint64Array)** Compacted cells sorted in curve order, then the [compaction marker](https://a5geo.org/next/docs/api-reference/compaction.md#coverings-and-the-compaction-marker)

#### Example

_Not yet in a released version for R._

```r
library(a5R)

cell <- a5_lonlat_to_cell(2.3522, 48.8566, resolution = 10)
compact <- a5_spherical_cap(cell, radius = 500000)  # 500 km
flat <- a5_uncompact(compact)  # all cells at resolution 10
```

# Compaction

Compaction is a way to efficiently represent a set of A5 cells by replacing groups of sibling cells with their parent cell. This reduces the number of cells needed to represent a region, while still standing for exactly the same set of cells.

For example, if you have all the children of a cell, you can represent them with just their parent cell. The `compact()` function performs this optimization, and `uncompact()` reverses it by expanding parent cells back into their children.

The result of a compaction is a [covering](https://a5geo.org/next/docs/api-reference/coverings.md), which automatically stores the resolution of the compacted cells in-band using a [compaction marker](#coverings-and-the-compaction-marker)

## Functions supporting compacted data

Many of the functions in the A5 API return and accept compacted data, and should be used whenever possible rather than using the more low-level functions below. See [here](https://a5geo.org/next/docs/api-reference/coverings.md#example-processing-flow) for an example.

- Indexing: [`a5_polygon_to_cells`](https://a5geo.org/next/docs/api-reference/indexing.md#polygontocells)
- Hierarchy: [`a5_cell_to_subcell`](https://a5geo.org/next/docs/api-reference/hierarchy.md#celltosubcells)
- Traversal: [`a5_grid_disk`](https://a5geo.org/next/docs/api-reference/traversal.md#griddisk), [`a5_grid_disk`](https://a5geo.org/next/docs/api-reference/traversal.md#griddiskvertex), [`a5_spherical_cap`](https://a5geo.org/next/docs/api-reference/traversal.md#sphericalcap)
- Set operations: [`a5_union`](https://a5geo.org/next/docs/api-reference/coverings.md#union), [`a5_intersect`](https://a5geo.org/next/docs/api-reference/coverings.md#intersect), [`a5_difference`](https://a5geo.org/next/docs/api-reference/coverings.md#difference)
- Predicates: [`a5_contains`](https://a5geo.org/next/docs/api-reference/coverings.md#contains), [`a5_overlaps`](https://a5geo.org/next/docs/api-reference/coverings.md#overlaps)
- Measures: [`a5_count`](https://a5geo.org/next/docs/api-reference/coverings.md#count), [`a5_area`](https://a5geo.org/next/docs/api-reference/coverings.md#area)

## Compaction helpers

### a5_compact

Compacts a set of A5 cells by replacing complete groups of sibling cells with their parent cells, and appends the [compaction marker](#coverings-and-the-compaction-marker) recording the resolution of the finest input cell. In most cases users will use [a5_polygon_to_cells](https://a5geo.org/next/docs/api-reference/indexing.md#polygontocells)

_Not yet in a released version for R._

```r
a5_compact(cells, resolution = NULL)
```

#### Parameters

- `cells` **(bigint[] | BigUint64Array)** Array of A5 cell identifiers to compact

#### Return value

- **(BigUint64Array)** Compacted cells sorted in curve order, then the [compaction marker](#coverings-and-the-compaction-marker). An empty input returns an empty array.

#### Example

_Not yet in a released version for R._

```r
library(a5R)

# Get 4 sibling cells at resolution 3
parent <- a5_cell("6a80000000000000")  # A cell at resolution 2
children <- a5_cell_to_children(parent)

# Compact them: they are stored as their parent, but still stand for 4 cells at resolution 3
compacted <- a5_compact(children)
a5_count(compacted)                # 4
a5_covering_resolution(compacted)  # 3
a5_uncompact(compacted)            # the 4 children again
```

### a5_uncompact

Expands a covering to all of its cells at the covering's resolution: the resolution of its [compaction marker](#coverings-and-the-compaction-marker), or of its finest cell when it has none.

_Not yet in a released version for R._

```r
a5_uncompact(x, resolution = NULL, simplify = TRUE)
```

#### Parameters

- `cells` **(bigint[] | BigUint64Array)** A covering, as returned by `a5_compact` or `a5_polygon_to_cells`

#### Return value

- **(BigUint64Array)** Array of cell identifiers, all at the covering's resolution

#### Example

_Not yet in a released version for R._

```r
library(a5R)

ring <- wk::wkt("POLYGON ((2.25 48.81, 2.42 48.81, 2.42 48.9, 2.25 48.9, 2.25 48.81))")
compacted <- a5_polygon_to_cells(ring, resolution = 10)

# No resolution needed: the compaction marker records it
flat <- a5_uncompact(compacted)
a5_get_resolution(flat[1])  # 10
```

#### Notes

- All output cells are at the covering's resolution; the [compaction marker](#coverings-and-the-compaction-marker) is not included
- The expansion is complete - every descendant cell at that resolution is included
- **Ordering property**: If the input is sorted in curve order (as `a5_compact` returns it), the output is too. All children of a cell form a contiguous, ordered block on the curve, so `a5_uncompact` on a covering produces sorted output without requiring a re-sort, which is useful for large result sets

### a5_covering_resolution

Returns the resolution a covering stands for: the resolution of its [compaction marker](#coverings-and-the-compaction-marker), or of its finest cell when it has none.

_Not yet in a released version for R._

```r
a5_covering_resolution(x)
```

#### Parameters

- `cells` **(bigint[] | BigUint64Array)** A covering, or any array of cells

#### Return value

- **(number)** Resolution (0–30), or -1 for an empty array or the [world cell](https://a5geo.org/next/docs/technical/index-encoding.md#special-case-world-cell)

#### Example

_Not yet in a released version for R._

```r
library(a5R)

parent <- a5_cell("6a80000000000000")  # resolution 2
compacted <- a5_compact(a5_cell_to_children(parent, resolution = 4))
a5_covering_resolution(compacted)  # 4
```

### isCompactionMarker

Checks whether a value is a [compaction marker](#coverings-and-the-compaction-marker), the value at the end of a covering that records its resolution. Most code never needs it: the A5 functions that read coverings handle the [compaction marker](#coverings-and-the-compaction-marker) themselves, and to get a covering's cells one at a time, use [`a5_uncompact`](#uncompact). Always keep the [compaction marker](#coverings-and-the-compaction-marker) when you store or pass on a covering, as without it the compacted cells no longer say which resolution they stand for.

_Not available in R._

#### Parameters

- `value` **(bigint)** Value from a covering

#### Return value

- **(boolean)** Whether the value is a [compaction marker](#coverings-and-the-compaction-marker)

#### Example

_Not available in R._

## Coverings and the compaction marker

A compacted array holds cells at mixed resolutions, but it stands for a set of cells at **one** resolution: compacting 8 cells at resolution 4 may leave 2 cells at resolution 3, which still mean those 8 cells. To keep that resolution, every compacted array ends with a **compaction marker**: a value in quintant 60 (only 0–59 exist), which no cell can take, recording the resolution of the set — for example `0xf00a000000000040` for resolution 10. We call such an array a *covering*, see [Coverings](https://a5geo.org/next/docs/api-reference/coverings.md) for the functions that combine, query and measure them.

- `a5_uncompact` reads the compaction marker, so it needs no resolution argument.
- The array is still a plain `BigUint64Array` of 64-bit values, so a covering stores as a single list column in a database, Parquet or Arrow — the resolution travels with it.
- `a5_cell_to_boundary` returns `[]` for the compaction marker, so rendering a covering draws only its cells.
- An array without a compaction marker is a covering too: its resolution is that of its finest cell.

Read coverings only through the A5 functions, which handle the compaction marker for you, rather than indexing the array or taking its length: [`a5_count`](https://a5geo.org/next/docs/api-reference/coverings.md#count) and [`a5_area`](https://a5geo.org/next/docs/api-reference/coverings.md#area) measure a covering, [`a5_contains`](https://a5geo.org/next/docs/api-reference/coverings.md#contains) tests a cell, [`a5_uncompact`](#uncompact) lists its cells at its resolution, and [`a5_covering_resolution`](#coveringresolution) gives that resolution.

`a5_compact`, [`a5_polygon_to_cells`](https://a5geo.org/next/docs/api-reference/indexing.md#polygontocells), [`a5_grid_disk`](https://a5geo.org/next/docs/api-reference/traversal.md#griddisk), [`a5_grid_disk`](https://a5geo.org/next/docs/api-reference/traversal.md#griddiskvertex), [`a5_spherical_cap`](https://a5geo.org/next/docs/api-reference/traversal.md#sphericalcap), [`a5_cell_to_subcell`](https://a5geo.org/next/docs/api-reference/hierarchy.md#celltosubcells) and the [set operations](https://a5geo.org/next/docs/api-reference/coverings.md) all return coverings. The cells come sorted in curve order (the order of the A5 space-filling curve), with the compaction marker last.

See [Bit Tags](https://a5geo.org/next/docs/technical/bit-tags.md#compaction-marker-encoding) for how the compaction marker is encoded.

# Coverings

A **covering** is a set of cells at one resolution, standing for an area of the globe, possibly in disjoint parts, such as the output of [`a5_polygon_to_cells`](https://a5geo.org/next/docs/api-reference/indexing.md#polygontocells) or [`a5_spherical_cap`](https://a5geo.org/next/docs/api-reference/traversal.md#sphericalcap). It is stored [compacted](https://a5geo.org/next/docs/api-reference/compaction.md), and in general should be used with methods expecting compacted data. If the actual cells are required (for example for a JOIN operation) a covering should be [uncompacted](https://a5geo.org/next/docs/api-reference/compaction.md#uncompact) first (warning: could use a huge amount of memory).

The functions on this page combine, query and measure coverings:

- [Set operations](#set-operations): [`a5_union`](#union), [`a5_intersect`](#intersect), [`a5_difference`](#difference)
- [Predicates](#predicates): [`a5_contains`](#contains), [`a5_overlaps`](#overlaps)
- [Measures](#measures): [`a5_count`](#count), [`a5_area`](#area)

## Example processing flow

```rust
// Construct coverings
let france = polygon_to_cells(&france_polygon, 18, None)?; // 944ms -> 1.09 billion cells
let germany = polygon_to_cells(&germany_polygon, 18, None)?; // 708ms -> 718 million cells
let near_bern = spherical_cap(bern, 400_000.0)?; // 302ms -> 1.02 billion cells
let near_luxembourg = spherical_cap(luxembourg, 150_000.0)?; // 113ms -> 143 million cells

// Set operations
let france_and_germany = union(&france, &germany)?; // 7.0ms -> 1.81 billion cells
let also_close_to_bern = intersect(&france_and_germany, &near_bern)?; // 5.4ms -> 646 million cells
let but_far_from_luxembourg = difference(&also_close_to_bern, &near_luxembourg)?; // 3.2ms -> 545 million cells

// Area of covering, to the nearest resolution 18 cell (~500m²)
println!("{} km²", area(&but_far_from_luxembourg)? / 1e6); // 1.4ms -> 269516 km²

// Point in polygon
println!("{}", contains(&but_far_from_luxembourg, munich)?); // 50ns -> true
```

Timings measured with the [Rust implementation](https://github.com/felixpalmer/a5-rs) on an Apple M1 Pro.

# Miscellaneous

### a5_migrate

Converts a cell ID from the legacy v0 A5 index to the format supported by A5 v1+. The mapping is fast because it only operates on the bit representation. The shape and positions of the cells do not change, so there is no need to re-index data from its original coordinates.

**Note this function will be retired in a future version, there is no plan to support the legacy v0 A5 index going forward**

_Not yet in a released version for R._

```r
a5_migrate(cell)
```

#### Parameters

- `cell` **(bigint)** A cell ID from the legacy v0 A5 index

#### Return value

- **(bigint)** The ID of the same cell in the v1 index

#### Example

_Not yet in a released version for R._

```r
library(a5R)

v0_cell <- a5_cell("59c4780000000000")  # Resolution 8 cell in the legacy v0 A5 index
a5_u64_to_hex(a5_migrate(v0_cell))      # "59c4280000000000"
```
